## 3. Schema Observations & Normalization Findings

1. **Dual Circle Tables (`circles` vs. `grid_circles`)**:
   - All foreign keys (`members.circle_id`, `committee_members.circle_id`, `membership_applications.circle_id`, `announcements.target_circle_id`, `knowledge_documents.circle_id`) reference `circles.id`.
   - `grid_circles` was added in migration `b72c9f4e8d11_v14_rc1_complete_21_table_schema.py` to satisfy the 21-table RC1 checklist.
   - **Recommendation**: Keep both tables synchronized during seeding (`import_official_member_list.py` already populates both `circles` and `grid_circles` with the exact same 20 official Diprokous Branch Committees / Grid Circles).
2. **Synced Membership & Payment Ledger Tables**:
   - `members` is synchronized with `memberships` and `membership_applications`.
   - `payment_transactions` is synchronized with `payments`.
3. **Cascade Delete Safety**:
   - Financial and audit records (`payment_transactions`, `certificates`, `audit_logs`, `application_reviews`) use `ON DELETE SET NULL` or `NO_ACTION` on `user_id` / `member_id` so historical financial and audit trails are never destroyed if an account is removed.
